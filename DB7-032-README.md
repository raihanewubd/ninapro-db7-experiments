# DB7-032: JOPS-inspired hierarchical Hudgins BRB

This experiment applies a budgeted hierarchical JOPS-inspired classification adaptation to the current NinaPro DB7 **EMG** BRB. It is not an EEG experiment or an exact replication of the paper's regression method. The 12 channel BRBs, all 48 MAV/WL/ZC/SSC inputs, AND-style rule matching and ER channel fusion remain. The changes are learned reference positions, searched reference counts and cooperative/block Differential Evolution for the constrained parameters.

The protocol remains S1–S20, E1 restimulus labels 1–17, training repetitions 1/3/4/6 and test repetitions 2/5. Windows are 200 ms, with 50 ms training stride and 10 ms test stride. Filtering and feature extraction reuse the verified DB7-030 implementation; final train-derived thresholds and raw input hashes match DB7-031. Test labels never choose features, references, structure or optimization settings.

Each subject/seed evaluates five structures: the initial all-three-reference and all-two-reference structures plus three SOHS-inspired add/prune proposals. Each attribute has 2–4 references. Ordered internal references are learned; fitting-data 5th/95th-percentile endpoints remain fixed. Initial rule beliefs use fitting-data class evidence. Rule weights, attribute weights, consequent beliefs and fusion weights also train.

The prespecified DE budget is population 12, four generations per block, two cycles over 12 channel blocks and a fusion block, mutation factor 0.5 and crossover probability 0.9. Fitness is full-fitting-data classification cross-entropy, evaluated in GPU chunks of 2,048 windows and four population members without subsampling the objective. This is a practical block-search adaptation, not the paper's full-vector DE or regression MAE/complexity guarantee. Parameter updates, initial/final accuracy and loss, and stagnation are exported for inspection.

Every structure uses four leave-one-training-repetition-out validation fits, including nested fitting-only ZC/SSC threshold screening. Selection maximizes mean validation accuracy, breaking ties by lower negative log likelihood then fewer rules. The Pareto archive uses **componentwise reference counts**: another candidate must have no worse validation accuracy and no more references in any of the 48 attributes, with at least one strict improvement, to dominate a candidate. This is different from considering total rule count alone. The chosen structure is refitted on all four training repetitions before test prediction. The three seeds are 42, 43 and 44: 300 structure evaluations, 1,200 validation BRB fits and 60 final fits. Two Kaggle T4 GPUs divide subjects between workers, and both are required.

Run `.github/workflows/db7-032-jops.yml`. It executes the engine and orchestration CPU self-tests, verifies the notebook/source hashes, submits once to the `beautifulminnd` Kaggle account using the existing secondary credentials, monitors progress and checks the completed archive. Supply `monitor_ref` to continue monitoring an existing kernel after a workflow timeout. Rerunning a submission attempt without `monitor_ref` is rejected to prevent duplicates. The GitHub monitoring budget is five hours inside a six-hour job; a longer Kaggle run can be monitored by a follow-up workflow without retraining.

The first full fit on each GPU produces a rough runtime forecast. A forecast exceeding nine hours for that worker aborts the full grid, terminates the other worker and preserves a partial archive. This prevents silently exhausting the Kaggle session or changing the agreed optimization budget. The appropriate continuation would split the same protocol into smaller runs. The forecast is approximate because subsequent candidate structures can have different rule counts. The runner downloads logs and partial archives on failure.

The notebook is `db7-032-jops-hierarchical-brb.ipynb`, generated by `scripts/build_db7_032_notebook.py`. The manifest records exact notebook and source hashes. Results are stored in `db7_032_results.zip`, then uploaded as GitHub artifact `db7-032-results-RUN_ID` with a SHA-256 verification record. Results include candidate structures, selection evidence, initial and trained rules/references/weights, histories, predictions, probabilities, accuracy/F1/confusions and subject-level uncertainty.

The matched comparator is the 48-feature EMG LDA; DB7-031 is the previous hierarchical BRB baseline. SI includes inertial modalities and is not a matched-input comparator. Previously inspected recordings remain exploratory evidence. Overlapping windows and repeated seeds are not independent subjects. No accuracy is claimed until completion and verification.

The historical DB7-031 comparison is **not an isolated optimizer ablation**. DB7-031 initialized every rule from the fitting-class prior. DB7-032 instead uses fitting-data activation/class evidence for each rule, then optimizes a jittered population. Initialization, reference positions/counts and optimization all change together. Any improvement establishes the combined method's performance under this protocol, not which one of those changes caused it. Initial/final exports and DE histories expose the contribution after empirical initialization.

Output recovery: the Kaggle CLI can download the complete results ZIP and then exit with an HTTP429 error from an additional API request. The runner now validates the downloaded ZIP immediately after each attempt, regardless of the CLI exit code. Acceptance requires ZIP CRC, matching source hashes, full experiment completion counts and all required report files. An incomplete, corrupt or mismatched archive still fails. Resume an existing completed kernel using `monitor_ref`; this does not launch training again.
